# Bagyt — персональный маршрут поступления

LOCUS Startup Hackathon 2026, кейс 02. Код кейса: **LOCUSCASE2**

Сервис превращает профиль абитуриента в маршрут: куда поступать, почему именно
этот вариант подходит и что нужно сделать следующим шагом.

- **Живая версия:** `<вставить ссылку на деплой>`
- **Вход не требуется** — состояние хранится в браузере, тестовый логин не нужен.

---

## 1. Задача

Поступление — это десятки решений: направление, вуз, пара профильных предметов ЕНТ,
пороговые баллы, гранты, документы, дедлайны. Информация разбросана по сайтам вузов,
НЦТ и eGov, а советы в интернете общие: «поступай на IT» или «вот список 50 вузов».
Абитуриент не понимает двух вещей: **что подходит именно ему** и **что делать сейчас**.

## 2. Решение

Один связный путь из семи этапов для конкретной аудитории — **ученик 11 класса
Казахстана, поступающий на бакалавриат по ЕНТ**.

| Этап | Что получает пользователь |
| --- | --- |
| 1. Вход | Что делает сервис и что будет на выходе |
| 2. Профиль | 7 вопросов: класс, интересы, балл ЕНТ, успеваемость, пара профильных предметов, языки, город и готовность к переезду, бюджет и приоритеты |
| 3. Диагностика | Сформулированная цель, ориентир по баллу, сильные стороны и ограничения |
| 4. Рекомендации | Программы с баллом соответствия и разбором шести критериев |
| 5. Сравнение | До трёх вариантов по 11 параметрам, приоритеты пользователя подсвечены |
| 6. Маршрут | 12–15 датированных шагов до августа 2027: экзамены, документы, дедлайны, активности |
| 7. Следующий шаг | Один выделенный шаг в закреплённой панели + отметка прогресса |

### Что отличает решение

**Объяснимость вместо «чёрного ящика».** Балл соответствия — взвешенная сумма шести
критериев. Под каждой карточкой сегментированная шкала: **ширина сегмента равна весу
критерия в модели, заливка — насколько он выполнен**. Кнопка «Почему подходит»
раскрывает все шесть компонентов с весом, баллом и текстом, содержащим конкретные
числа: «Грант здесь закрывался на 98 баллах: это на 8 баллов ниже вашего ориентира».

**Формальные правила приёма как жёсткий фильтр.** Сервис различает «не советуем» и
«нельзя». Пара профильных предметов ЕНТ и пороговый балл направления — формальные
барьеры: такие программы уходят в блок «Закрыто формально» с объяснением, что
именно мешает и как это исправить. Это главное, что отсутствует в обычных подборках.

**Реакция на изменение ответа.** Прямо на экране рекомендаций стоят пять чипов
быстрой правки (балл, бюджет, интересы, профильные предметы, география). После
сохранения сервис не просто пересчитывает выдачу, а показывает **что изменилось**:
какие программы появились и ушли, как сдвинулись шансы на грант, изменился ли лидер.

**Честность о данных.** Проверяемые факты (вуз, город, языки, требуемая пара
предметов, сайт) отделены от демонстрационных ориентиров (проходной балл, стоимость,
число грантов, оценки репутации). Демонстрационные числа везде помечены значком
«демо», у календарных шагов стоят ссылки на НЦТ и eGov. Сервис не обещает гарантий
поступления и не показывает выдуманной точности.

## 3. Стек

| Слой | Решение | Почему так |
| --- | --- | --- |
| Фронтенд | Нативный JavaScript (ES-модули), без фреймворка | 72 часа: ноль времени на конфигурацию и ноль риска, что сборка упадёт перед демо |
| Стили | Один CSS-файл с токенами дизайн-системы | Цвета, типографика, состояния — в одном месте |
| Логика подбора | Собственный rule-based движок | Детерминированный и объяснимый: одинаковый профиль всегда даёт одинаковый результат |
| Состояние | `localStorage` через свой store | Полный путь работает без бэкенда, кейс это прямо разрешает |
| Сборка | `build.py` — склейка в один файл | `dist/index.html` открывается даже с диска, без сервера |
| Тесты | Node + jsdom, 33 проверки | Сквозной прогон пути и сценария проверки жюри |

**Шрифт:** Onest (Google Fonts) — единственная внешняя зависимость.
Фреймворков, UI-kit-ов и готовых компонентов нет: вся вёрстка и дизайн-система
написаны в рамках хакатона.

## 4. Архитектура

```
index.html            точка входа, подключает модули
assets/styles.css     дизайн-система: токены, компоненты, адаптив
src/
  data/
    taxonomy.js       направления, пары профильных предметов ЕНТ,
                      пороговые баллы, города, бюджеты, плюрализация
    programs.js       каталог из 50 программ 23 вузов; у каждой записи
                      указано, какие поля демонстрационные
  lib/
    scoring.js        движок: компоненты, шансы на грант, блокировки,
                      ранжирование по слоям, диагностика профиля
    plan.js           генератор маршрута по циклу ЕНТ
    store.js          состояние, localStorage, вычисление изменений
  ui/
    screens.js        отрисовка всех экранов (чистые функции → HTML)
  app.js              контроллер: состояние → пересчёт → перерисовка
build.py              сборка dist/index.html
tests/                engine / ui / dist
```

**Поток данных односторонний:** состояние → `derive()` пересчитывает диагностику,
рекомендации, маршрут и следующий шаг из одного источника → полная перерисовка.
Поэтому экраны физически не могут разойтись между собой: правка бюджета на шаге 7
немедленно меняет и рекомендации, и сравнение, и план.

### Модель подбора

Отбор в три слоя:

1. **Формальные требования.** Пара профильных предметов ЕНТ и пороговый балл
   направления (нацвузы — 65, право и педагогика — 75, здравоохранение — 70,
   агро — 60, остальные — 50). Не выполнены → программа недоступна.
2. **Релевантность.** Прямое совпадение с интересом и география. Смежные
   направления и другие города не вытесняют то, что человек искал, — они уходят
   в отдельный блок. Если прямых совпадений меньше трёх, лучшие смежные
   поднимаются в основной список с честной пометкой почему.
3. **Балл соответствия.** Взвешенная сумма: интересы 28%, шансы на поступление 26%,
   бюджет 20%, город 12%, язык 9%, профильные предметы 5%.

Шансы на грант считаются как разрыв между ориентиром абитуриента и проходным баллом
программы, с поправкой на объём грантов, и переводятся в пять уровней от «высокие»
до «маловероятен». Ожидаемый балл корректируется на успеваемость (±6), уже
полученный — нет; это показано пользователю явно.

## 5. Как запустить

ES-модули требуют http, поэтому для модульной версии нужен любой локальный сервер:

```bash
git clone <репозиторий>
cd bagyt
python3 -m http.server 4321      # или: npx serve .
# открыть http://localhost:4321
```

Одностраничная сборка работает и без сервера:

```bash
python3 build.py                 # собирает dist/index.html (~124 КБ)
# dist/index.html можно открыть двойным щелчком
```

Тесты (нужен Node 18+ и `npm i` для jsdom):

```bash
npm install
npm test                         # 33 проверки: движок, интерфейс, сборка
```

**Деплой:** статика без сборки. GitHub Pages — включить Pages для ветки `main`,
корень репозитория. Vercel / Netlify — залить папку как есть, build command пустой.

## 6. Тестовый сценарий для жюри

Проверочный сценарий из кейса воспроизводится за две минуты:

1. **Пройти путь.** «Заполнить анкету» → 11 класс → интересы «Программирование и IT»
   и «Данные, AI и аналитика» → балл 104, успеваемость «в основном четвёрки» →
   пара «Математика — Физика» → языки русский и английский → Алматы, готов
   переехать → до 2 млн ₸, приоритет «Шансы на грант» → «Показать диагностику».
2. **Проверить объяснимость.** На любой карточке нажать «Почему подходит»: шесть
   критериев с весом, баллом и числами; у закрытых программ — конкретное правило
   приёма, которое мешает.
3. **Изменить ответ.** На экране рекомендаций чип «Бюджет» → «Только грант» →
   «Сохранить и пересчитать». Появляется блок «Ответ изменён» с перечнем изменений.
   То же с чипом «Профильные»: смена пары на «Биология — Химия» полностью меняет
   доступный набор программ.
4. **Сравнение.** Отметить «Сравнить» на двух–трёх карточках → «Сравнить».
   Строки с приоритетами помечены звёздочкой, лучшие значения — зелёным.
5. **Маршрут и следующий шаг.** «Построить маршрут»: план с датами, ссылками на
   НЦТ и eGov, пометками «демо» у неподтверждённых дат. Отметить шаг — прогресс
   и панель «Следующий шаг» обновляются.
6. **Мобильная версия и состояния.** Сузить окно до 380 px — путь работает в одну
   колонку. Пустые состояния: сравнение с одним вариантом, профиль без интересов,
   запрет сохранения в приватном режиме браузера.

## 8. Источники данных

**Проверенные факты:**

- Формат и сроки ЕНТ, пробные тесты — Национальный центр тестирования,
  <https://testcenter.kz/>
- Регистрация на основное ЕНТ-2026 (11–25 апреля) и период тестирования
  (10 мая — 10 июля) — сообщения МНВО РК и НЦТ, апрель 2026
- Пороговые баллы ЕНТ-2026: нацвузы 65, прочие 50, право и педагогика 75,
  здравоохранение 70, агро и ветеринария 60
- Конкурс на грант идёт на группу образовательных программ, а не на отдельную
  специальность; заявление — через eGov или приёмную комиссию, <https://egov.kz/>
- Вуз, город, языки обучения, требуемая пара профильных предметов, ссылка —
  официальные сайты вузов (указаны в каждой карточке)

**Демонстрационные данные** (в интерфейсе помечены «демо»):

- проходные баллы на грант — ориентиры по прошлым кампаниям;
- стоимость обучения и объём грантов — порядок величин;
- оценки репутации и трудоустройства — редакционные, не официальный рейтинг;
- даты кампании 2027 — сдвиг календаря 2026, официально не объявлены.

Коды групп образовательных программ (B057, B046, B049, B086 и др.) указаны только
там, где подтверждены; в остальных карточках поле пустое, а не заполнено догадкой.

## 9. AI, API и внешние сервисы

**LLM и внешние API не используются.** Это осознанное решение, а не ограничение:

- кейс прямо разрешает rule-based логику;
- подбор обязан быть воспроизводимым — жюри меняет один ответ и должно видеть
  предсказуемое изменение, а не новую генерацию;
- каждое объяснение собирается из реальных чисел модели, поэтому сервис не может
  выдумать проходной балл или дедлайн — а именно это в кейсе прямо запрещено.

Объяснения формируются шаблонами, в которые подставляются значения компонентов.
Внешних запросов нет вообще: данные абитуриента не покидают браузер.

## 10. Готовые компоненты

Нет. Фреймворки, UI-kit-ы, CSS-библиотеки и генераторы не использовались.
Единственная внешняя зависимость продукта — шрифт Onest с Google Fonts.
`jsdom` используется только в тестах и в продукт не попадает.

## 11. Ограничения

- Одна страна и один уровень образования: бакалавриат Казахстана по ЕНТ.
  Зарубежные программы вне фокуса — кейс разрешает такую фокусировку.
- Каталог из 50 программ 23 вузов, а не полный реестр. Структура записи готова
  к расширению: добавление программы — одна запись в `programs.js`.
- Проходные баллы и стоимость демонстрационные; для реального использования нужна
  выгрузка НЦТ и парсер сайтов вузов.
- Без бэкенда: профиль живёт в одном браузере, аккаунтов и синхронизации нет.
- Оценка шансов — сравнение с проходными баллами прошлых лет, а не прогноз
  конкурса. Сервис говорит об этом прямо и не даёт гарантий.
- Nazarbayev University включён как пример отдельного трека отбора (не по ЕНТ):
  сервис честно сообщает, что балл ЕНТ там ничего не решает.

## 12. Куда развивать

1. Выгрузка проходных баллов и грантов из НЦТ вместо ручного каталога.
2. Калькулятор балла по пяти предметам с прогнозом от результатов пробных тестов.
3. Подбор стипендий и напоминания о дедлайнах.
4. Расширение на колледжи, магистратуру и зарубежные программы.
5. Аккаунты и общий доступ: маршрут виден родителю и школьному психологу.
